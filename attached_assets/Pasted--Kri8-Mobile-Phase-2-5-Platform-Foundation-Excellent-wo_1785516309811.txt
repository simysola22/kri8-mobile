# Kri8 Mobile — Phase 2.5 (Platform Foundation)

Excellent work on Phase 2.

The architecture is clean and should remain the foundation of the mobile application.

Do **NOT** redesign the UI.

Do **NOT** rebuild the navigation.

Do **NOT** rewrite the authentication.

Do **NOT** duplicate existing code.

Instead, continue building on the existing architecture.

The goal of this phase is to strengthen the platform before beginning Camera, Voice, OCR and other advanced mobile features.

---

# IMPORTANT

Do NOT break any existing functionality.

Everything completed in Phase 2 must continue working.

The application must continue compiling successfully after every major change.

If a new feature requires architectural changes, implement them in a backwards-compatible manner.

---

# FEATURE 1 — BIOMETRIC SECURITY

Implement native biometric authentication.

Support:

• Face ID

• Touch ID

• Android Fingerprint

Allow users to enable biometric unlock from Settings.

After successful authentication with Clerk, users should be able to unlock the app using biometrics instead of repeatedly entering credentials.

If biometrics fail:

Fall back to device PIN or Clerk authentication.

The feature should be optional.

---

# FEATURE 2 — LOCAL DRAFT RECOVERY

Implement automatic draft persistence.

If the application crashes while the user is writing:

Idea text

Notes

AI prompts

Voice transcript

must all be restored automatically.

Users should never lose work because the application closed unexpectedly.

---

# FEATURE 3 — UNIVERSAL SEARCH

Create a global search architecture.

Searching should simultaneously search:

Ideas

Friends

Messages

AI conversations

Trends

Tags

Calendar

Saved inspiration

The user should only have one search box.

Results should be grouped by category.

Searching should be extremely fast.

Prepare the architecture for server-side search later.

---

# FEATURE 4 — SMART CAPTURE DETECTION

Prepare the Capture workflow to intelligently identify content.

Examples:

Plain text

URLs

YouTube links

TikTok links

Instagram links

X posts

Voice recordings

Images

Screenshots

The application should automatically determine the correct workflow without asking unnecessary questions.

Do not fully implement OCR yet.

Only build the intelligent routing architecture.

---

# FEATURE 5 — BACKGROUND SYNCHRONIZATION

Improve the existing offline queue.

When connectivity returns:

Synchronize automatically.

Do not require users to reopen the app.

Support:

App resumes

Network reconnect

Background refresh where supported

Display subtle synchronization indicators.

Never interrupt the user.

---

# FEATURE 6 — AI ASSISTANT EVERYWHERE

AI should become an invisible assistant.

While the user types:

Suggest:

Better titles

Hooks

Descriptions

Tags

Content categories

Posting platforms

Posting times

Improve clarity

Generate alternative wording

Do NOT create a separate AI page for these actions.

AI assistance should feel contextual and automatic.

---

Prepare notification architecture.

Friend requests

Messages

Trend alerts
