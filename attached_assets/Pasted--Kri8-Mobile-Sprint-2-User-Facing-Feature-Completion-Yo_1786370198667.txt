# FEATURE 1 — BIOMETRIC SECURITY

Use the existing:

* BiometricService
* useBiometric

Do not create another biometric service.

## Settings

Add a proper biometric security section to Settings.

It should:

* Detect whether biometrics are available.
* Detect supported biometric type where possible.
* Show whether biometric protection is enabled.
* Allow the user to enable/disable biometric protection.
* Require successful biometric verification when enabling/disabling if appropriate.
* Persist the setting safely.
* Handle devices without biometric hardware gracefully.

Example:

Security

Biometric App Lock
Protect Kri8 when the app returns from the background.

[ Face ID / Fingerprint ]

The UI must work with the existing theme system.

## App lock

When biometric protection is enabled:

* Lock the application when it returns from the background according to the existing app lifecycle architecture.
* Display a clean Kri8 lock screen.
* Trigger the biometric prompt.
* Do not repeatedly trigger prompts in an infinite loop.
* Handle cancellation gracefully.
* Allow the user to retry.
* Provide a safe fallback path to sign in again if the existing authentication architecture supports it.

Do NOT create fake authentication.

Do NOT bypass Clerk.

Do NOT store passwords.

Do NOT store biometric credentials.

Use the operating system's biometric APIs through the existing BiometricService.

## Edge cases

Handle:

* biometric hardware unavailable
* biometric permission denied
* user cancels prompt
* too many failed attempts
* device does not support biometrics
* app starts for the first time
* user logs out
* user switches accounts
* app resumes multiple times

# SMART TEXT CAPTURE

When the user enters text into the capture screen:

Run the existing CaptureDetectionService.

It should detect supported URLs/platforms such as:

* YouTube
* TikTok
* X/Twitter
* general URLs

Do not invent unsupported extraction capabilities.

When a supported URL is detected, show a useful contextual UI.

Example:

Detected link

TikTok

[ Add to Idea ]

or:

Detected YouTube link

[ Save ] [ Cancel ]

Do not block normal text capture if detection fails.

Detection failure must be non-fatal.

---

# DRAFT RECOVERY

Integrate useDraft into the capture flow.

While the user is creating/editing content:

* Save drafts automatically using the existing DraftService.
* Avoid excessive writes.
* Debounce draft persistence where appropriate.
* Preserve the draft when the app is backgrounded or unexpectedly closed.
* Associate drafts with the correct user/account where the existing architecture supports it.

When a recoverable draft exists:

Show a clean recovery UI.

Example:

Recovered draft

"10 ways to grow on TikTok..."

[ Restore ]

[ Discard ]

Restore:

→ populate the capture/editor with the draft.

Discard:

→ permanently remove the draft through DraftService.

Do not silently overwrite user content.

If both a current unsaved draft and a recovered draft exist, clearly ask the user which one they want to keep.
